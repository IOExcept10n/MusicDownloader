# MusicDownloader: доработка (дизайн)

Дата: 2026-11-06. Код: `source/` (Avalonia 11, .NET 8, MVVM, TagLibSharp). Язык документа и UI: русский.

## Зачем

Приложение — личный менеджер локальной музыкальной библиотеки. Рабочий поток владельца:

1. Найти трек во вкладке «Онлайн-сервисы», скачать, прослушать фрагмент (убедиться, что это тот трек).
2. В «Библиотека → Неотсортированные» нажать «Найти теги»: приложение собирает данные из Last.fm, Genius, LRCLib и др.
3. Разрешить конфликты, дозаполнить пропуски (особенно номер трека, год, обложку).
4. Выделить всё и одним действием переместить в библиотеку (заранее заданная папка).
5. Иногда перепроверять теги уже скачанных треков.

Доступ к музыке VK закрыт, и приложение потеряло источник треков. Заодно накопились боли:
ручной поиск и дозаполнение тегов; не видно, скачался трек или нет; обложки приходится искать руками;
тексты песен приходится искать руками; дизайн кода плох.

## Цели

1. **Надёжные теги.** Исправить дефекты Last.fm-провайдера (см. ниже), проверять совпадение трека у Genius, добавить новые источники тегов (минимум MusicBrainz + Cover Art Archive; дополнительно iTunes Search и Deezer для обложек и поиска по «исполнитель + название» без знания альбома).
2. **Правила автотеггера (решение владельца).**
   - Никогда не перезаписывает уже заполненные теги без явного разрешения владельца. Может советовать.
   - Пустое поле заполняет само, если источники не противоречат друг другу.
   - При конфликте источников решает только владелец; приложение показывает рекомендацию (например, два источника вернули X, один Y — рекомендуем X).
3. **Экран результатов тегирования — вариант B (выбран владельцем).** Список всех обработанных треков: готовые (конфликтов нет, обязательные теги заполнены, см. «Правила заполненности») помечены ✅, сомнительные ⚠️/❌ с причиной и кнопкой действия («Выбрать», «Проверить», «Ввести»). Кнопка «Применить готовые (N)». По кнопке на сомнительном треке открывается детальная таблица «поле × источник» с рекомендацией.
4. **Обложки.** Кандидаты из нескольких источников показываются миниатюрами с размером в пикселях, наибольший предпочитается как рекомендация, выбор за владельцем. Сохранить существующую кнопку «обложка по ссылке из буфера»; добавить вставку картинки из буфера, выбор файла/перетаскивание, кнопку «найти обложку в браузере».
5. **Тексты.** Кнопка «Найти текст песни в браузере» (открывает веб-поиск по «исполнитель + название»). Текст из LRCLib остаётся автоисточником.
6. **Статусы загрузки — вариант B (выбран владельцем).** Статус виден прямо в строке трека в результатах поиска: можно скачать / в очереди / процент / готово (в неотсортированных) / уже в библиотеке / ошибка с причиной и «повторить». Дубли не скачиваются повторно. Ошибки загрузки больше не глушатся.
7. **Источники треков.** Архитектура поддерживает несколько источников одновременно (сейчас `IMediaProvider` один на всё приложение). Конкретный новый источник — отдельный экспериментальный этап в конце (см. ниже).
8. **Чистка кода по ходу работ** (не отдельным проектом): логика из code-behind в ViewModel/сервисы; убрать `App.Services` там, где трогаем код; убрать `.Wait()`/`GetAwaiter().GetResult()`; логирование, не теряющее ошибки; обновление списков после переноса; проверка существования целевого файла при переносе.

## Правила заполненности и конфликтов (решения владельца)

- **«Заполнено» = осмысленное значение.** Пустое, 0, «Unknown…» и название, просто повторяющее имя файла, считаются пустыми, и автотеггер заполняет их сам. Остальное он без явного разрешения не трогает.
- **Уже записанное значение — ещё один источник** при конфликте: попадает в таблицу «поле × источник» как вариант и по умолчанию остаётся выбранным; сменить его может только владелец.
- **Два уровня заполненности сохраняются как в коде** (`TrackViewModel`: `RequiredTags`, `RecommendedTags`, состояния `Untagged` / `Incomplete` / `Complete`):
  1. *Обязательные:* название (`Title`), исполнители (`Performers`). Без них трек `Untagged`.
  2. *Рекомендуемые:* альбом, жанры, год, номер трека и обложка. Когда заполнены и они, трек `Complete`; иначе `Incomplete`.
- **«Готов» (✅, входит в «Применить готовые»)** = нет конфликтов и заполнены обязательные теги. Полнота второго уровня показывается отдельно (Complete / Incomplete) и на готовность не влияет.
- **Особые теги** (то, что не входит ни в один из двух уровней: текст, описание, комментарий, подзаголовок, диск и число дисков, исполнители альбома, роли, число треков в альбоме) учитываются отдельно: на уровень не влияют и показываются своим индикатором. *Моя трактовка: «особые» = все остальные теги из `Tags.AllTags`; виртуальные теги вроде `State`, `HasCover` в файл не пишутся и сюда не входят.*

## Не цели

- Не восстанавливаем вход в VK (его способ входа — под видом Android-клиента — ненадёжен).
- Не переписываем UI-фреймворк, не меняем формат библиотеки/имён файлов и не ломаем уже скачанные файлы.
- Не делаем стримингового плеера (прослушивание фрагментов уже есть, остаётся как есть).
- Не обходим DRM/шифрование ни в каком источнике.

## Анти-цели (провал, даже если технически работает)

- Перезапись тегов, которые владелец заполнил, без его явного согласия.
- Обложка или любое поле, выбранное при конфликте источников молча.
- Тихо проглоченная ошибка: пользователь не должен гадать, скачался ли трек.
- Сломанная сборка на другой машине (пути `G:\Study\...` в `MD.csproj`) — чинится по пути.

## Известные дефекты, которые надо исправить (по коду, `LastFmProvider.cs` и др.)

- Номер трека: сравнение названия точное, с учётом регистра, по локальному названию; при несовпадении получается 0, а 0 считается «нет значения» (`Tag<T>.HasValue`) — тег молча пропадает.
- Год: из `album.ReleaseDateUtc`, которого у Last.fm часто нет — снова 0.
- Для треков без `AlbumName` альбомный запрос пропускается целиком; альбом ищется по локальному имени исполнителя, а не по тому, что вернул Last.fm.
- Genius берёт первый результат без проверки совпадения; текст скрейпится регуляркой; год читается через `dynamic`.
- Токен Genius передаётся в query, токены попадают в debug-логи; токены лежат в открытом `.tokencache`.
- Подробнее по структуре: `DirectoryTracksProvider` (`path.Contains`, `isDirty` не сбрасывается), `MetadataManager.SaveMetadata` (файл не освобождается), `MediaLibrary.MoveTrack` (нет проверки существующего файла).

## Порядок работ (решение владельца)

1. Теги: исправления Last.fm/Genius, новые источники, правила автотеггера, экран B, обложки, кнопки поиска текста и обложки в браузере.
2. Статусы и очередь загрузок (вариант B), честная обработка ошибок.
3. Чистка кода — по ходу двух предыдущих этапов.
4. Источник треков — последний, небольшой, экспериментальный этап. Кандидат владельца: zvuk.com (подписка у владельца). Неофициальный доступ может сломаться в любой момент и может противоречить условиям сервиса — решение об использовании принимает владелец, обход DRM исключён.

## Ограничения

- Остаёмся на Avalonia/.NET 8, существующих `IDetailProvider`/`ILyricsProvider`/`IMediaProvider` (расширяем, не заменяем).
- Ключи Last.fm/Genius владелец вводит сам в настройках, как сейчас. Новые ключи не вшиваем в код.
- Внешние API нестабильны: каждый источник должен отказывать независимо и с понятной ошибкой.
- Тестов почти нет (~29, ни одного на провайдеры): новые парсеры и логику выбора/рекомендации покрываем тестами на записанных ответах, без сети.

- Детали визуала сверх макетов (`.superpowers/brainstorm/.../content/*.html`).

## Допущения исполнителя (моё решение, а не владельца)

- Макеты в `.superpowers/brainstorm/*/content/` (`download-queue.html`, `tag-conflicts.html`) — эскизы, не пиксельные требования; в репозиторий не коммитятся (`.superpowers/` в `.gitignore`), исполнитель воссоздаёт раскладку сам.
- Перенос в библиотеку остаётся как сейчас: плоская папка, имя `{N:D3}. Исполнитель - Название.mp3`. При совпадении имени файла приложение спрашивает (пропустить / заменить / оставить оба), молча не перезаписывает.
- «Уже в библиотеке» определяется по нормализованной паре «исполнитель + название» среди отслеживаемых папок и неотсортированных (регистр, пунктуация и скобки типа `(feat. ...)` игнорируются).
- Пока нет рабочего источника (до этапа 4), этапы 1–2 проверяются на тестовом/заглушечном `IMediaProvider` и на файлах, положенных в «Неотсортированные» вручную; этап 4 можно поднять раньше по просьбе владельца.
- Этап 4 (zvuk.com): сначала короткий эксперимент. Критерий: если поток отдаётся без шифрования обычным запросом с авторизованной сессией владельца — можно продолжать; если требуется обход шифрования/DRM — этап останавливается. Решение «использовать или нет» принимает владелец. Офлайн-режим мобильного приложения Звука — это, как правило, зашифрованный кэш внутри приложения, а не экспорт файлов, так что его наличие не означает разрешения на сохранение файлов.
- Токены вместо открытого `.tokencache` шифруются средствами Windows (DPAPI, на пользователя); существующий файл один раз переносится в новый формат.
- Тестовые ответы API пишутся вручную по публичной документации; владелец может позже записать реальные ответы своими ключами.

- Приложение остаётся только для Windows-пользователя-одиночки; кроссплатформенность Avalonia не расширяем.
- Поведение «пустое поле + нет конфликта = заполнить» применяется и к обложке, если кандидат один; при нескольких разных кандидатах обложка считается конфликтом.
